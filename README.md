# معبد باستت بتل بسطة — نموذج التراث الرقمي

نموذج بحثي أكاديمي عربي يدعم اتجاه RTL، صُمم لرسالة دكتوراه بهدف عرض معبد باستت بصورة رقمية مبسطة، وتحسين تجربة الزائر، وشرح مفهوم حماية البيانات الأثرية الرقمية.

تم تحديث هذا النموذج ليصبح نموذجاً متكاملاً (Full-Stack) يحتوي على واجهة خلفية (FastAPI Backend) وقاعدة بيانات (PostgreSQL Database) ونظام تذاكر وصلاحيات حقيقي.

## التقنيات المستخدمة

- **الواجهة الأمامية (Frontend):**
  - React وVite
  - React Router (HashRouter)
  - CSS responsive مخصص
  - Phosphor Icons
  - Matterport Embed SDK للجولة ثلاثية الأبعاد ونقاط القطع المعتمدة
  - Axios للاتصال بالخادم وإدارة الجلسات الآمنة (Memory-only Access Tokens & HttpOnly Cookies)

- **الواجهة الخلفية (Backend):**
  - FastAPI
  - SQLAlchemy 2.x
  - PostgreSQL
  - Alembic لإدارة هجرات قاعدة البيانات
  - Argon2id لتشفير كلمات المرور بشكل آمن
  - Pytest للاختبارات الآلية

## قبل أن تنقل المشروع إلى جهاز آخر

المشروع لا يعمل بمجرد نسخ المجلد. المجلدات التالية **مرتبطة بالجهاز الذي أُنشئت عليه**
ويجب حذفها قبل الإرسال، ثم إعادة توليدها على الجهاز الجديد:

| المجلد | السبب |
|---|---|
| `backend/.venv/` | يحتوي مسارات مطلقة لمفسّر بايثون على الجهاز الأصلي، وسيفشل على أي جهاز آخر |
| `node_modules/` | روابط pnpm الرمزية لا تنجو من النسخ أو الضغط |
| `dist/`, `test-results/`, `playwright-report/`, `.pytest_cache/`, `backend/dev_emails/` | مخرجات مؤقتة، لا لزوم لها |

كذلك ملفا `.env` و`backend/.env` يحتويان مفاتيح سرّية (`SECRET_KEY`, `ADMIN_PASSWORD`).
**لا ترسلهما.** أرسل `.env.example` بدلاً منهما وليملأهما المستلم بقيمه.

المتطلبات على الجهاز الجديد: **PostgreSQL** و**Python 3.12** و**Node.js** مع **pnpm**.
قاعدة البيانات نفسها لا تُنقل مع المشروع — تُنشأ من جديد بالخطوات أدناه.

## التشغيل والتهيئة محلياً

### 1. إعداد قاعدة البيانات (PostgreSQL)
تأكد من أن خادم PostgreSQL يعمل على جهازك محلياً. قم بإنشاء قاعدتي بيانات (واحدة للتطوير والأخرى للاختبارات):

```sql
CREATE DATABASE bastet_temple;
CREATE DATABASE bastet_temple_test;
```

### 2. إعداد الواجهة الخلفية (Backend)
انتقل إلى مجلد `backend` وقم بإنشاء بيئة افتراضية وتثبيت الحزم:

```powershell
cd backend
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
```

قم بإنشاء ملف الإعدادات البيئية `backend/.env` بناءً على النموذج `backend/.env.example` واملأ المتغيرات المطلوبة (مثل `SECRET_KEY` وقاعدة البيانات).

بعد ذلك، قم بتشغيل هجرات قاعدة البيانات عبر Alembic:

```powershell
alembic upgrade head
```

ثم قم بإنشاء حساب المسؤول الأول (Admin). يقرأ السكريبت بيانات المسؤول من `backend/.env`،
لذلك يجب ضبط `ADMIN_EMAIL` و`ADMIN_PASSWORD` **قبل** تشغيله (كلمة المرور 15 حرفاً على الأقل):

```powershell
python -m app.seed
```

لتشغيل خادم التطوير للواجهة الخلفية:

```powershell
uvicorn app.main:app --reload --port 8000
```

يمكنك التحقق من صحة عمل الواجهة الخلفية عبر الرابط:
* الصحة: `http://127.0.0.1:8000/api/v1/health`
* التوثيق التفاعلي (Swagger): `http://127.0.0.1:8000/docs`

### 3. إعداد الواجهة الأمامية (Frontend)
تأكد من إعداد ملف `.env` في المجلد الرئيسي للواجهة الأمامية وتعيين المتغيرات المناسبة:

```env
VITE_API_BASE_URL=http://localhost:8000
VITE_MATTERPORT_TOKEN_ID=ystsaqrf43nktz8km90c9gbfd
VITE_MATTERPORT_CALIBRATION=true
```

قم بتثبيت الحزم وتشغيل الواجهة الأمامية:

```powershell
# في المجلد الرئيسي للمشروع
pnpm install
pnpm run dev
```

## تشغيل الاختبارات الآلية (Testing)

لتشغيل اختبارات الواجهة الخلفية بالكامل والتأكد من توافق كافة المسارات والصلاحيات (31 حالة اختبار):

```powershell
cd backend
.venv\Scripts\activate
pytest -q
```

لتشغيل اختبارات الواجهة الأمامية وبناء نسخة الإنتاج:

```powershell
pnpm test
pnpm run build
```

## الجولة التخيلية وتصاريح الدخول

تعرض الصفحة نموذج Matterport الحقيقي ذي المعرّف `SFcW4AeVYWM`.

**إنشاء الحساب:** يسجّل الزائر حساباً ويدخل مباشرة — لا توجد خطوة تفعيل بالبريد الإلكتروني.

**صلاحية دخول الجولة:** الزائر الجديد **لا يستطيع** فتح الجولة التفاعلية افتراضياً. يفتح المسؤول
تبويب «قائمة المستخدمين» في لوحة الإدارة، ويجد لكل حساب عمود «الجولة التفاعلية» بزر **السماح / المنع**.
هذا المفتاح يعمل في الاتجاهين وفي أي وقت: يمكن السماح ثم المنع ثم السماح مجدداً، دون أن يقدّم الزائر أي طلب.
حساب المسؤول لديه صلاحية دائمة.

**الأدوار:** دوران فقط — `visitor` و`admin`.

## لوحة الإدارة
تحتوي على ثلاثة تبويبات:
* **قائمة المستخدمين** — كل الحسابات المسجّلة، وتغيير الدور، والتعليق وإعادة التفعيل وفك القفل، ومفتاح صلاحية الجولة.
* **التقييمات** — كل التقييمات المُرسَلة مع البريد الإلكتروني لصاحب كل تقييم ودرجاته وملاحظاته.
* **سجل التغييرات الأمني** — سجل الأحداث الأمنية.

## اللغة
يدعم الموقع العربية (RTL) والإنجليزية (LTR) بالكامل عبر زر تبديل اللغة في الشريط العلوي.
جميع النصوص في `src/i18n/ar.js` و`src/i18n/en.js` — لا تكتب نصوصاً مباشرة داخل المكوّنات.

## أمن المعلومات وحماية البيانات
* يتم حفظ جلسات وتذاكر الدخول في قاعدة البيانات كمرجع وحيد للحقيقة.
* يتم تمرير رمز التحديث (Refresh Token) عبر كوكيز مشفرة ومحمية من نوع `HttpOnly` لضمان الحماية من هجمات XSS.
* تمت إضافة حماية ضد الهجمات المتكررة وسحب البيانات عبر قيود برمجية للتحقق والحد من الطلبات.
