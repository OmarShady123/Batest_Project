# Bastet Temple Digital Prototype - Codex Notes

- Scope: Arabic RTL academic Vite/React SPA for the Bastet Temple at Tell Basta. Preserve the current visual language and never invent archaeological identities, dates, descriptions, or image attribution.
- Architecture: `src/main.jsx` boots `HashRouter`; routes/pages live in `src/App.jsx`; shared navigation/search/theme/footer live in `src/components/Layout.jsx`. The project now includes a backend using FastAPI, SQLAlchemy, Alembic, PostgreSQL, Redis-backed production rate limiting, and real authentication and account security.
- Matterport: model SID is `SFcW4AeVYWM`. `src/components/MatterportViewer.jsx` owns the Embed SDK/current Tag API and card synchronization; `MatterportCalibrationPanel.jsx` is development-only. Data/persistence/validation live in `src/data/{artifact-pool,hotspots}.js` and `src/utils/hotspot{Store,Validation}.js`.
- Accuracy invariant: normal visitors may see only artifact and hotspot records that are both `verified`. Never use CSS/screen percentages or sweep positions as artifact anchors. Save Showcase world coordinates from Pointer/Renderer intersections, plus floor/sweep/provenance/reviewer fields. Do not use deprecated Mattertag APIs.
- Matterport media: app-relative images belong in the custom detail card. Register a native Tag attachment only from an explicit public HTTPS `matterportMediaUrl`; never send localhost, data, or relative asset URLs to Matterport.
- Current content: five visitor mappings are committed. Candidate 01 is spatially verified but deliberately unattributed; candidates 03-06 are official-source visual matches for the Bastet lioness head, Ramesses VI, Ramesses II triad, and Corinthian capital. Candidate 02 (Queen Meritamun) remains hidden because tested sweeps returned no raycastable surface. Candidates 07-08 remain unmatched. The six former generic-block captures are `removed` audit evidence in `RETIRED_BLOCK_CAPTURE_INVENTORY`. Calibration storage is version 7.
- Calibration: set `VITE_MATTERPORT_CALIBRATION=true` for development only. The SDK key is `VITE_MATTERPORT_SDK_KEY`; the old `VITE_MATTERPORT_TOKEN_ID` name is compatibility-only. Never invent env values or expose calibration in production.
- Commands: `pnpm install --frozen-lockfile`, `pnpm run dev`, `pnpm run test:unit`, `pnpm run validate:hotspots`, `pnpm test`, `pnpm run build`, `pnpm run preview`. No lint/typecheck scripts currently exist. Run builds serially.
- Verification: for Matterport changes, test SDK connection, exact marker/card mapping, refresh persistence, camera/sweep movement, mobile/desktop, RTL, and production build. Report manual verification gaps honestly.
- Conventions: React function components, plain CSS, Phosphor icons, accessibility labels, responsive RTL. Keep edits scoped and update `PROJECT_CONTEXT.md` when architecture or mapping rules change.
- Avoid unnecessary edits to `dist/`, backup zip, lockfile, public fonts/assets, `.env`, and static-hosting headers. Do not hand-edit generated build output. Treat localStorage and the information-security page as prototype behavior, not real security. Never reuse an unmatched candidate image for another object; leave the image missing until the object is visually matched.
